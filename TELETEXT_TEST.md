# Experimental page 100 on RGB SCART

V080A adds a fixed System B Teletext output fixture to the firmware-only V079Z
core. It is a cable/TV experiment, not live broadcast Teletext or a firmware
Teletext service. Native firmware execution remains entirely in the FPGA.

1. Load `Pace2500N_V080A_Live.mgl` and allow the normal cold boot.
2. Press **F11** on the MiSTer keyboard (or map that key on the USB IR adapter).
3. On the **TV's own remote**, select Text and page **100**.
4. F11 again cancels the test. It also stops automatically after **30 seconds**.
   Press F11 again for another window if needed. A loaded/restarted core always
   starts with the experiment off and ordinary composite sync.

This needs native 625-line RGB and `composite_sync=1`. Scaled/scandoubled,
component and Y/C modes are excluded. No MiSTer.ini changes are made. RGB, VSync,
audio and GPIO output drive strengths are unchanged. Only the existing HSync/
CSync output carries the experimental waveform while the window is active.

The one-bit output uses zero for sync, a 50/127 pulse-density black pedestal,
and full available pin level for Teletext data one. Existing attenuation remains
in circuit. This preserves the relative sync/data ratio at reduced amplitude;
TV input filtering and gain determine whether decoding works. Successful digital
simulation does not establish analogue waveform compliance or TV compatibility.
If the TV loses sync, cancel with F11 or wait for the 30-second timeout.

Page 100 includes `PACE 2500N / MISTER`, explanatory text and coloured labels.
It repeats rows 0–24 at one packet per field, with a full page every 0.5 seconds.
Clock run-in, framing, Hamming address/header and odd-parity characters are
generated by `tools/make_teletext_test_page.py`. The serializer runs at exactly
37/288 of 54 MHz, averaging 6.9375 Mbit/s. Packets begin about 10.28 microseconds
after HSync, on a blanking line in each field.

Validation before Quartus: physical-output simulation covers both fields,
7/8-clock bit durations, framing, pedestal density, unchanged inactive sync,
start/cancel, timeout and wrong/missing HSync guards. Unmodified libzvbi 0.2.42
independently decodes the serialized page and verifies its text. UART regression
covers all eight FP/video/Teletext diagnostic combinations; full core lint runs
with the optional interface enabled.

The build watcher compiles a frozen source snapshot, records non-HDMI timing,
uploads and verifies the RBF hash, boots original flash with EEPROM and live TS,
then tests UART CPU/flash health, PAL lock, advancing packet counters, automatic
timeout and manual cancellation. A failed hardware check restores V079Z. A pass
leaves V080A running with the experiment off. SSH screenshots show FPGA RGB;
they cannot capture the TV's independently generated Teletext display.

`TT=` UART status: bit31 active, bit30 PAL line lock, bit29 packet busy, bit28
test window open, bits20:16 next row, bits15:0 completed packet count. The status
bus is diagnostic only, not used for firmware or control decisions.

Build with `PACE_TELETEXT_TEST=1`; without that macro the platform's original
HSync assignment and core interface remain in use. The frozen V079Z RBF/MGL
remain available as the working fallback. This is an experimental local build;
timing reports and actual TV observation must accompany any later feature claim.

21 Nov 2026 result: V080A compiled and all 48 non-HDMI timing checks passed
(minimum setup +0.266 ns, hold +0.256 ns). Two 190-second hardware captures
confirmed exact original flash, healthy firmware execution, PAL lock, packet
progress, 30-second expiry and manual cancel. The first automatic window sent
exactly 1,500 packets. RGB screenshots before/during/after were pixel-identical.
The first verifier hit a malformed UART frame; its parser was fixed and the
complete hardware test repeated successfully. Malformed frames are counted and
reported, with limits; readable CPU halts remain failures. V080A was left running
with the experiment off. Physical TV observations follow.

The first user photo showed the header only. A second photo and user report
confirm body text and colours decode on the Sony CRT through the existing
MiSTerPi analogueIO/SCART cable. The user reports about **20 seconds** of repeated
transmission before the page stabilised. This demonstrates reception on that
setup; acquisition speed/reliability still needs improvement. No error rate or
compatibility with other TVs has been measured.

If only the header appears, leave TV Text on and press F11 on MiSTer to start
a fresh transmission window; the TV may have retained a header from an earlier
test after the 30-second window ended. Allow time for acquisition. A longer
temporary test window and controlled acquisition tests are candidates for the
next revision; the current build still has its 30-second limit.
